# 分野プロファイル `F` の根拠（O*NET 由来）

`config/fields.py` の `field_profile`（10分野 × 5軸 = 50値）の導出過程を記録する。
以前の値は「各分野の人によくある性格」を書き手の感覚で当てた仮値で、
根拠がどこにも残っていなかった（`docs/presentation.md` 付録 A.5）。
本ドキュメントはその置き換えである。**50セルすべてが公開データの数値から機械的に決まる。**

---

## 1. データ源

**O*NET Database 30.0（Text 配布版、米国労働省・公開データ）**

```
https://www.onetcenter.org/dl_files/database/db_30_0_text.zip
  Work Styles.txt   … 職業ごとの性格特性の重要度
  Interests.txt     … Holland RIASEC の職業興味
  Abilities.txt     … 認知能力の重要度
  Knowledge.txt     … 知識領域の重要度
  Skills.txt        … スキルの重要度
  Work Activities.txt … 一般作業活動の重要度
```

O*NET は職業ごとに就業者調査（Incumbent survey）と専門家評価から記述子を数値化している。
**Work Styles は職業別のパーソナリティ重要度そのもの**であり
（Attention to Detail ≒ Big Five の誠実性、Innovation ≒ 開放性）、
**Interests は Holland の RIASEC 六角形**である。本モデルの5軸はこれらの合成で表す。

尺度は Work Styles / Abilities / Knowledge / Skills / Work Activities が **1〜5（重要度）**、
Interests が **1〜7（職業興味）**。尺度が違うので、合成前に軸ごとにzスコア化する。

## 3. 5軸 → O*NET 記述子の対応

軸の定義はアンケートのプロンプト文（`inputs/data/user_input_1.csv` のヘッダー）に合わせた。

| 5軸 | アンケートでの定義 | O*NET 記述子（すべて平均） |
| --- | --- | --- |
| クリエイティブ | ゼロから何かを生み出す・デザインする志向 | Innovation (1.C.7.a) / Thinking Creatively (4.A.2.b.2) / Originality (1.A.1.b.2) / Fluency of Ideas (1.A.1.b.1) |
| ロジカル | 仕組みや理屈を理解したい。論理的・分析的 | Analytical Thinking (1.C.7.b) / Investigative (1.B.1.b) / Deductive Reasoning (1.A.1.b.4) / Inductive Reasoning (1.A.1.b.5) |
| 作る↔運用 | 新しく作る ↔ 既存を安定的に管理・改善 | Artistic (1.B.1.c) − Conventional (1.B.1.f) |
| 数学 | 数式・計算・統計・データ分析 | Knowledge: Mathematics (2.C.4.a) / Skill: Mathematics (2.A.1.e) / Mathematical Reasoning (1.A.1.c.1) / Number Facility (1.A.1.c.2) |
| 計画性・正確さ | 計画を立て、手順やルールを守り、正確にやり遂げる | Attention to Detail (1.C.5.b) / Dependability (1.C.5.a) / Information Ordering (1.A.1.b.6) / Conventional (1.B.1.f) |

**1軸につき指標を3〜4本使っているのは、O*NET の重要度スケールが専門職の間で
ほとんどばらつかないためである**（例：Attention to Detail は1〜5尺度で 4.40〜4.91 の範囲にしか散らばらない）。
単一指標だと 0.05 の差が最終値の 0.25 の差に化けるので、複数指標の平均で均す。

## 4. 変換規則

```
1. 指標ごとに10分野でzスコア化する（尺度の違いを吸収する）
2. 軸に属する指標のzスコアを平均する（＝合成zスコア）
   ※「作る↔運用」だけは双極軸なので z(Artistic) − z(Conventional)
3. 合成zスコアを10分野で min–max 正規化して 0〜1 に収める
4. 0.25刻みへ丸める
```

**なぜ min–max で、順位ではないのか**：順位で均等割りすると、誤差の範囲でしかない
差（数学軸の中位8分野は合成zが ±0.2 の中に固まっている）が必ず 0.25 の差として出てしまう。
min–max なら僅差の分野は同じ値に丸まり、実際に離れている分野だけが離れる。

**なぜ 0.25 刻みなのか**：元データの分解能がその程度だからである。
0.1 刻みにすると「なぜ 0.7 で 0.6 ではないのか」に答えられないセルが出る。

**満たすべき不変条件**（`tools/profile_check.py` が検査する）

- 各軸に 0.00 の分野と 1.00 の分野が最低1つずつある
  → その軸で◎と答えた人と×と答えた人が別の分野へ導かれる
- まったく同一のプロファイルを持つ分野が無い
  → 旧プロファイルはフロントエンドとモバイルアプリが完全に同一で、
    適性からは原理的に区別できなかった（`docs/presentation.md` 付録 A.1 の警告）

## 6. データが通説と食い違った点（そのまま採用した）

**旧プロファイルは書き手の直感で作られていたので、直感と違う値が出た箇所こそが今回の改訂の中身である。**
以下はいずれも直感を採らず O*NET の数値を採った。

| 箇所 | 通説 | O*NET | 採用した理由 |
| --- | --- | --- | --- |
| グラフィックデザインの計画性 | 低い（旧値 0.0） | Attention to Detail 4.80（10分野中3位）／Dependability 4.65（1位） | 締切と入稿規定に追われる職業であり、几帳面さは実際に高い。Conventional が低い分だけ最終値は 0.25 に落ち着いた |
| バックエンドの「作る↔運用」 | 作る側（旧値 1.0） | Artistic 2.26（9位）／Conventional 5.46（4位） | O*NET は**プログラミング全般を Conventional（手順・情報の整理）に強く分類する**。したがって本モデルのこの軸は実質「デザイン志向 ↔ 運用志向」に近い |
| フロントエンドとモバイルアプリ | 同一（旧値は完全一致） | Investigative 5.06 vs 5.46 など、モバイルの方がやや分析寄り | 完全一致は解消したが平均二乗距離 0.0125 と依然近い。この2分野が性格上ほぼ同じであること自体は事実である |
| 数学軸の中位 | 分野ごとに差がある | データ/ML（+2.60σ）とグラフィックデザイン（−1.37σ）以外の8分野は ±0.2σ に密集 | **数学の適性で分かれるのはデータ/ML かどうかだけ**、というのがデータの言い分。8分野を横並びの 0.25 にした |

## 7. 既知の限界

- **「クリエイティブ」と「作る↔運用」の相関が高い**（合成zスコアで r = +0.95）。
  IT10分野では「創造性が高い分野」＝「デザイン寄りの分野」であり、
  O*NET のどの記述子を使っても両者は分離しなかった（Thinking Creatively と
  Artistic−Conventional のどちらで組んでも順位はほぼ同じ）。
  5軸の実効的な自由度は4強しかない。軸の再設計は今後の課題。
- **UI/UXデザインとデータ/ML は代用職業**である（§2）。O*NET 30.0 に評価値が入り次第、
  15-1255.00 と 15-2051.00 へ差し替えるべきである。
- **順位が誤差の範囲である軸がある**（§6 の数学軸）。min–max 正規化で
  僅差は同じ値へ丸まるようにしてあるが、丸め境界に乗っている分野
  （インフラ/クラウドの数学 0.379）は次のデータ更新で動きうる。

## 8. 検証結果

`tools/profile_check.py` の出力より（5軸を {0.0, 0.5, 1.0} で全数列挙した243パターン）。

| 指標 | 旧プロファイル＋旧式 | 新プロファイル＋正規化 |
| --- | --- | --- |
| 分野平均のばらつき（構造バイアス） | 0.152 | **0.059** |
| 同一プロファイルの分野 | フロントエンド＝モバイルアプリ | **なし**（最接近 0.0125） |
| 0.00 と 1.00 が揃っている軸 | — | **5/5** |
| 候補0件になるパターン | 15 / 243（`RuntimeError`） | 1 / 243（フォールバックで救済） |

**自己申告との一致（実回答5件）**：レポートの【興味のある分野】に挙げた分野のうち、
相性が閾値を超えて推薦計算に使われたものの割合。

| 回答 | 申告した分野 | 採用された分野 |
| --- | --- | --- |
| r1 | フロントエンド、モバイルアプリ、ゲーム開発 | **3 / 3** |
| r2 | バックエンド、QA・テスト | **2 / 2** |
| r3 | バックエンド、インフラ/クラウド | 1 / 2（インフラ 0.48 で僅差の除外） |
| r4 | UI/UXデザイン、バックエンド、QA・テスト | 1 / 3 |
| r5 | UI/UXデザイン、Webサイト管理、フロントエンド | 2 / 3（旧設定では候補0件でエラー） |

適性5軸だけから計算した相性が、独立に申告された興味と 9/13 で一致している。
興味は推薦計算に一切入れていない（`docs/requirements.md` 第12節）ので、
これは**プロファイルの妥当性に対する外部からの裏付け**として読める。
